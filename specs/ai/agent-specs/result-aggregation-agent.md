# Agent Specification: Result Aggregation Agent

## 1. Purpose
This agent is a **deterministic function**, not an LLM agent. Its purpose is to take all the calculated and generated data for the matched candidates and format it into the final response structure required by the API (FR-2).

## 2. Inputs
- The agent receives the entire `GraphState` as input.
- It specifically operates on:
  - `state.candidate_scores`
  - The explanation strings generated by the `Explanation_Generation_Agent`.

## 3. Core Logic (Deterministic)
The agent will perform the following steps:
1.  **Sort Candidates**: Sort the `candidate_scores` list in descending order based on `final_score`.
2.  **Derive `fit_level`**: For each candidate, map their `final_score` to a `fit_level` enum (`HIGH`, `MEDIUM`, `LOW`) based on configurable thresholds.
   - e.g., `final_score >= 0.70` -> `HIGH`
   - e.g., `0.40 <= final_score < 0.70` -> `MEDIUM`
   - e.g., `final_score < 0.40` -> `LOW`
3.  **Combine and Format**: For each candidate, create a `FinalResult` object by combining:
   - `team_member_id` from `candidate_scores`.
   - A rounded `profile_score` (e.g., `final_score * 100`).
   - The derived `fit_level`.
   - `availability_match` from `candidate_scores`.
   - The `explanation` strings from the `Explanation_Generation_Agent`.
4.  **Create Final List**: Compile all the `FinalResult` objects into a single list.

This logic will be encapsulated in a pure Python function. **No LLM is involved.**

## 4. Outputs
- The agent's output is a list of `FinalResult` objects, as defined in `state-schema.md`.
- This agent mutates the graph state by populating the `state.final_results` field. This field contains the clean, ordered list of candidates ready for the API response.

## 5. State Mutations
- **Allowed**:
  - Sets the `state.final_results` field.
- **Forbidden**:
  - Must not modify any other part of the state.

## 6. Guardrails & Failure Handling
- **Configuration**: The thresholds for `fit_level` must be loaded from a configuration file and should not be hardcoded.
- **Data Integrity**: The agent must handle cases where some data might be missing (e.g., if an explanation was not generated for a candidate) and use appropriate defaults.
- **Failure**: As this is a simple data transformation step, errors should be minimal. However, any unexpected errors must be caught, logged, and propagated to the `state.error_message`.
